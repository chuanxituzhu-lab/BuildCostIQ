# BuildCostIQ 新手上手流程：费曼学习法

本教程面向“第一次使用造价数字化工具”的造价员。目标不是记住按钮，而是完成一个可复核的项目成果闭环：

```text
项目建档 → 资料归档 → 合同/清单/图纸 → 零号台账 → 成本计划
→ 变更 → 证据 → 工程事件 → 结算初审 → 成果经营 → 导出交付
```

## 一、先记住一句话

把工程资料变成三类东西：

1. **事实**：合同、清单、图纸、数量、单价、变更和证据；
2. **判断**：成本是否可比、变更是否需要决策、结算是否可发布；
3. **成果**：实体是否形成、证据是否完整、是否申报、是否确认、是否结算、是否回款。

P01–P08 保存专业事实，P09 只读取这些事实并生成成果经营视图。系统不会用一个猜测数字覆盖原始事实。

## 二、费曼学习法怎么用

每完成一个步骤，都做四件事：

| 环节 | 新手要做什么 |
|---|---|
| 讲人话 | 用一句不带术语的话说明这一步解决什么问题 |
| 动手做 | 在 WebUI 完成一次真实操作 |
| 自己复述 | 不看教程，再说一遍输入、输出和依据 |
| 找漏洞 | 检查是否缺资料、缺来源、缺责任人或口径冲突 |

如果不能用一句话说明“输入什么、产出什么、凭什么”，就不要进入下一步。

## 三、开始前准备

建议使用脱敏练习项目，不要直接拿正式项目试错。准备以下资料：

- 合同正文、补充协议、招投标文件；
- 工程量清单（Excel/CSV 或表格）；
- 施工图、设计变更图、图纸会审记录；
- 开工基线或零号台账；
- 合同单价、市场参考价及其价格口径；
- 变更、签证、会议纪要、现场照片；
- 结算清单、收方资料、付款或回款记录。

启动工具：

```powershell
cd "F:\造价数字化BuildCostIQ"
.\.venv\Scripts\Activate.ps1
buildcostiq-web --port 8787
```

打开 `http://127.0.0.1:8787/`，先注册或登录本地账号。

## 四、逐步操作

### 第 1 步：项目建档

**讲人话**：先给工程建立一个“文件夹和身份证”。

**怎么做**：

1. 打开“项目总览”；
2. 输入项目名称；
3. 点击“保存项目”；
4. 确认当前项目名称出现在顶部。

**自测复述**：

> 我现在操作的是哪个项目？如果换项目，资料会不会混在一起？

**完成标志**：顶部显示正确项目，后续资料都在当前项目内保存。

**常见错误**：项目名称写成“测试项目1”，以后无法判断资料属于哪个工程。练习时也要使用清楚的名称，例如“道路项目-演示-2026”。

### 第 2 步：接入并整理初步资料

**讲人话**：先把文件安全放好，再谈计算。原件是证据，识别稿只是辅助阅读。

**怎么做**：

1. 在“项目总览”点击“接入初步资料”或“＋接入资料”；
2. 一次选择合同、图纸、照片、Excel、PDF、Word 等文件；
3. 等待本地保存和识别状态更新；
4. 用“查看”打开原件，用识别稿快速搜索；
5. 不要删除或覆盖原件。

**自测复述**：

> 哪个是原始文件？哪个是识别出来的 Markdown？如果识别错了，我应该回到哪里核对？

**完成成果**：项目资料库、原始文件路径、分类归档位置、识别状态和可回溯来源。

### 第 3 步：P01 合同与招采依据

**讲人话**：P01 解决“我们到底按什么合同干活、谁承担什么责任”。

**怎么做**：

1. 进入“01 合同与招采依据”；
2. 按招标、投标、定标、合同、执行解释归档资料；
3. 填写合同编号、项目名称、合同金额、双方、税制、开竣工日期；
4. 录入关键义务：事项、责任方、截止日期、金额、状态；
5. 点击“保存合同资料”。

**自测复述**：

> 合同范围是什么？谁负责？什么时候完成？哪份资料能证明？

**完成成果**：合同主数据、义务清单、缺失字段提示、合同资料来源。

**不要做**：不要把图纸、现场照片、结算清单全部塞进 P01；它们应进入对应阶段。

### 第 4 步：P02 工程量清单

**讲人话**：P02 把“表格里的工程量”变成系统能核对的标准条目。

**怎么做**：

1. 进入“02 清单资料”；
2. 选择 Excel/CSV，或直接录入表格；
3. 核对编码、名称、单位、工程量；
4. 检查无效编码、缺单位、负工程量和重复行；
5. 保存清单结果。

**自测复述**：

> 这一行是什么项目？单位是什么？工程量来自哪一份表？

**完成成果**：标准化清单条目、数量、单位、来源和待核对项。

**新手检查口诀**：编码对不对、名称清不清、单位一致不一致、数量有没有来源。

### 第 5 步：P03 图纸登记

**讲人话**：P03 不替你做 CAD 算量，它先确保“用的是哪一版图纸”。

**怎么做**：

1. 进入“03 图纸资料”；
2. 登记图号、名称、专业、版本、状态、来源；
3. 标记待审、已审、已批准或已作废；
4. 保存图纸登记。

**自测复述**：

> 这条工程量对应哪张图、哪个版本？旧图是否已作废？

**完成成果**：图纸登记册、版本链、待审图纸清单、来源链接。

### 第 6 步：P04 零号台账

**讲人话**：P04 是项目开局时的“起跑线”，以后所有偏差都和它比较。

**怎么做**：

1. 进入“04 零号台账”；
2. 录入编码、名称、单位、数量、单价、金额、基准口径和来源；
3. 能由数量×单价计算的金额让系统计算；
4. 对未定价条目保留“待定价”，不要猜一个价格；
5. 保存台账。

**自测复述**：

> 这个基线是在什么时候形成的？金额从哪里来？哪些项目还没有价格？

**完成成果**：零号台账、基线金额、未定价清单、基线来源。

### 第 7 步：P05 成本计划

**讲人话**：P05 把清单和合同单价连接起来，形成可解释的成本计划。

**怎么做**：

1. 进入“05 成本计划”；
2. 确认 P02 清单条目已接入；
3. 填写合同/中标单价；
4. 如需比较市场价，单独录入市场参考价并声明含税、价格类型、来源和日期；
5. 查看待组价、合同小计和口径可比状态；
6. 保存成本计划。

**自测复述**：

> 哪个数字是合同基线？哪个数字只是市场参考？两者为什么可以或不可以直接比较？

**完成成果**：合同成本计划、待组价清单、口径声明、可比/冲突提示和成本控制结果。

**重要规则**：市场参考价不会偷偷改写合同成本计划；口径冲突时系统不输出伪造的偏差结论。

### 第 8 步：P06 变更管理

**讲人话**：P06 记录“发生了什么变化、影响多少、谁决定、现在到哪一步”。

**怎么做**：

1. 进入“06 变更管理”；
2. 录入变更标题、原因、金额影响、责任人、影响日期、状态和来源；
3. 对待审批项目保留 pending，不要直接写成 approved；
4. 保存变更登记。

**自测复述**：

> 这是事实还是判断？谁批准？批准前能不能把它当成最终金额？

**完成成果**：变更台账、待决策队列、净影响汇总、责任人和来源。

### 第 9 步：P07 证据关联

**讲人话**：P07 把“说过、做过、算过”连接到能证明它的资料。

**怎么做**：

1. 进入“07 证据关联”；
2. 选择目标记录，例如合同、图纸、变更、清单或结算事项；
3. 关联照片、签字单、会议纪要、指令、图纸版本和计算表；
4. 标记待核验或已核验；
5. 保存证据链接。

**自测复述**：

> 如果审计人员问“凭什么”，我能否从这条记录点回原始资料？

**完成成果**：可回溯证据链、未核验证据清单、来源和审计轨迹。

### 第 10 步：Core 工程事件内核

**讲人话**：工程事件是把跨专业问题串起来的“主线编号”，不是另建一个任务系统。

**怎么做**：

1. 进入“Core 工程事件内核”；
2. 先点击“蒸馏本地资料”，让系统读取当前项目事实；
3. 如有现场记录或会议纪要，再粘贴文本并点击“蒸馏文本并融合”；
4. 检查事实、来源、冲突和待核对主张；
5. 确认标题、事件类型、严重度、位置、时间、影响维度和来源；
6. 保存永久事件编号；
7. 按事实推进 Event 状态，不要为了好看跳过审批或核验。

**自测复述**：

> 这件事何时发现？影响什么？谁判断？下一步动作是什么？证据在哪里？

**完成成果**：永久 Event 编号、状态历史、生产/技术/商务信息、证据检查和风险提醒。

### 第 11 步：Outcome 成果快照

**讲人话**：工程做完不等于钱已经实现；Outcome 单独记录成果转化到了哪一步。

**怎么做**：

1. 在工程事件卡片中打开 Outcome；
2. 选择成果类型：实体、经营、合同权利、工期或现金；
3. 追加快照：实体完成、证据完整、已申报、已确认、收入成立、已结算、已回款；
4. 每次修订写明原因，系统保留历史版本；
5. 根据真实依据推进 Outcome 状态；
6. 如果被拒绝、放弃或发生反审，记录原因，不覆盖原事实。

**自测复述**：

> 事件已经关闭了吗？成果是否已确认？确认金额和回款金额是不是同一个状态？

**完成成果**：Outcome 状态机、快照修订历史、成果类型、失败原因和待转化阶段。

### 第 12 步：P08 结算初审

**讲人话**：P08 用确定性规则先抓算术和结构错误，减少人工漏检。

**怎么做**：

1. 进入“08 结算初审”；
2. 选择清单和结算资料；
3. 检查合价、编码、重复项、单位、数量、口径和资料完整性；
4. 查看 block、warn、info 三类结果；
5. 先处理 block，再处理 warn，最后阅读 info；
6. 只有满足发布门禁时，才进入发布流程。

**自测复述**：

> 这条问题是算术错误、资料不足，还是需要人工判断？它的判定依据是什么？

**完成成果**：审查发现、判定依据、风险等级、可发布/不可发布结论和审查快照。

### 第 13 步：P09 全过程成果经营

**讲人话**：P09 是项目经理每天看“价值有没有真正落地”的经营台。

**怎么做**：

1. 点击“09 成果经营”；
2. 先看成果漏斗：实体完成 → 证据完整 → 已申报 → 已确认 → 收入成立 → 已结算 → 已回款；
3. 再看价值泄漏：在哪一段掉了、掉了多少、原因是否补齐；
4. 最后看今日经营队列：哪些事件有预警、未闭环或长期打开；
5. 回到对应的 P06、P07、Core 事件或 P08 处理，不在 P09 直接修改专业事实。

**自测复述**：

> 当前最大的损失发生在哪一段？下一步应该补证据、申报、确认、结算还是回款？

**完成成果**：成果漏斗、价值泄漏清单、异常经营队列、P01–P08 事实覆盖情况和数据不足提示。

## 五、一个完整练习案例

用“地下管线冲突”练习：

1. P03 登记现场图纸版本；
2. Core 创建“地下管线冲突”事件；
3. P07 关联现场照片、指令和会议纪要；
4. P06 登记变更原因、预计影响和审批状态；
5. 现场完成后，在 Outcome 记录实体成果和证据完整度；
6. P08 检查相关清单和结算资料；
7. Outcome 逐步推进到申报、确认、结算和回款；
8. P09 查看哪一段发生价值泄漏，并回到对应页面补齐。

练习结束时，你应能回答：

> 这件事从哪里开始？依据是什么？谁做了决定？形成了什么成果？为什么还没有全部变成回款？

## 六、最终应交付什么成果

一次完整项目操作，至少应形成：

- 项目资料库和原始文件归档；
- P01 合同与义务清单；
- P02 标准化工程量清单；
- P03 图纸登记册和版本链；
- P04 零号台账；
- P05 成本计划和口径比对；
- P06 变更台账和待决策队列；
- P07 可回溯证据链；
- Core 工程事件及状态历史；
- Outcome 快照和成果转化状态；
- P08 结算初审结果；
- P09 成果漏斗、价值泄漏和经营队列；
- Word 兼容报告、Excel 清单/成本计划或项目交换包；
- 审计记录和来源链。

## 七、新手验收清单

完成以下问题，说明已经基本熟悉：

- [ ] 我能建立项目并接入资料；
- [ ] 我能区分原件、识别稿和业务记录；
- [ ] 我能说出 P01–P09 各自负责什么；
- [ ] 我能从成本数字回到清单、合同和价格口径；
- [ ] 我能从变更回到图纸、指令、照片和审批；
- [ ] 我能解释 Event 关闭和 Outcome 实现的区别；
- [ ] 我能从 P09 找到价值泄漏，再回到正确的业务页面处理；
- [ ] 我能导出一份别人可以复核的项目成果包。

## 八、操作原则

1. 原件不覆盖，历史只追加；
2. 没有来源就标记待核对，不凭经验补数字；
3. 市场参考价不自动替代合同价；
4. 待审批不写成已批准；
5. Event 关闭不代表成果已回款；
6. P09 只看问题和转化，不在 P09 复制或修改专业事实。
