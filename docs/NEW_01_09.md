# 新版 01–09 业务流程说明

适用范围：一个施工项目部。模块 06 是共享底座，不单独建立业务单；其余八项使用同一套身份权限、证据引用、审批、验收、版本记录、恢复和交接机制。

## 模块工作面

| 编号 | 工作流 | 主要记录与人工关口 |
| --- | --- | --- |
| 01 | 造价依据（政府行业文件） | 文件名称、发布机关、编号、适用地区、有效期和范围；复核来源/版本后纳入项目依据目录。 |
| 02 | 投标工作流 | 招标条件、清单/价格依据、报价版本；依次复核技术条件、工程量与报价、项目投标决策和递交归档。 |
| 03 | 中标工作流 | 中标通知、投标版本、合同编号及合同金额；复核中标/合同差异，确认合同基准并验收归档。 |
| 04 | 施工中造价工作流 | 现场/变更事件、实物量、合同依据和造价影响；由现场、技术、造价、项目经理和造价岗位分步复核与验收。 |
| 05 | 竣工结算工作流 | 合同版本、送审/复核金额、工程量依据、差异和成果包；分开记录外部审定与内部意见，完成审批及归档。 |
| 06 | 共享造价能力底座 | 为其他模块提供项目身份、角色权限、追加式事件账本、结果版本、证据校验、人工审批/验收、检查点、重放和岗位交接。 |
| 07 | 工程量计算复核 | 图纸版本、清单项、单位、计算式和候选量；复核图纸范围与计算过程，由责任人确认验收量。 |
| 08 | PDF/CAD/BIM 提量工具 | 登记源文件、版本、专业、方法、比例/坐标、候选量及局限；复核提量条件并抽核结果。该流程记录提量工作，不等同于所有格式都已具备自动几何提量引擎。 |
| 09 | 施工项目试验报告系统 | 报告、机构、样品、材料批次、使用部位、日期和原件结论；绑定质量责任并完成报告归档。系统不自动判断实体合格。 |

## 通用操作闭环

1. 有权限的岗位创建草稿并填写本模块要求的字段。
2. 选择已归档到当前项目的证据；系统保存证据摘要引用，不把其他项目的资料作为本项目证据。
3. 提交后依模块定义逐步进入复核、审批和专业验收。审批人须有对应岗位权限，不能由发起人或已在本流程签署的人重复签署。
4. 每个通过步骤必须完成专业检查清单并关联项目证据；退回或拒绝必须说明原因。补正形成新版本，既有版本与决定留在账本中。
5. 通过专业验收后，只能按已定义的下游流程和岗位发起交接；接收人独立签收，交接内容仅供下游复核。
6. 工作流页面依据校验通过的本地事件账本重建状态。账本不完整或哈希校验失败时停止读取，不猜测或补写审批事实。

## Sayelf Agent Ops 边界

人员管理还提供本地岗位识别建议：管理员填写岗位名称和职责后，规则可建议试验检测员、施工员、生产经理或技术负责人，并预览该岗位当前固定权限。匹配冲突时要求管理员核对；建议不会自动建号、发邀请或授予权限。

Agent Ops 为当前业务工作生成和记录最小计划。`READY` 只表示计划已形成，不代表已运行、审批或验收。业务字段、造价结论、外部审批、专业判断和最终决定仍由相应岗位人员承担；本次不新增 Skill 或 Agent。

## 明确边界

- 本版提供 01–05、07–09 的单项目人工流程面和追踪机制，不声称替代各专业工具或项目审批制度。
- 01 不自动抓取或判定政府文件的适用性；08 不声称通用 PDF/CAD/DWG/IFC 几何提量已全部实现；09 不自动判定试验/实体合格。
- 不自动作出投标、合同、变更或结算决策，不新增第二金额事实源，不扩展为 Enterprise、多项目或 ERP。
- 项目资料、图纸、报价、合同、结算和试验报告保存在本地项目数据根，不进入 GitHub 源码发布。
