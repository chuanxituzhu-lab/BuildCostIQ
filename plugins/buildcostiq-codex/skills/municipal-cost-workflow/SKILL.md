# 市政项目岗位工作流

这个 Skill 适用于已经登记在 BuildCostIQ 项目中的项目经理、造价经理、造价员、技术负责人、生产经理、施工员/测量员、质量负责人、试验检测员、资料员、安全员、采购员、仓管员和行政人员。它只编排已有 Core、P01–P09、权限和 WebUI，不新增 Core 能力或第二金额事实源。

## 先确认边界

- 本地 MCP 通过 stdio 连接，不需要 OpenAI API Key；岗位身份来自 `BUILDCOSTIQ_MCP_ACTOR` 对应的本地人员登记。
- 只把当前人员所属项目和当前岗位契约展示给用户。项目经理和造价经理可以看到 P09 派生摘要，其他岗位看到自己的工作面。
- P04 零号台账、成本计划和敏感金额只能由造价经理或造价员按现有权限处理；不要让其他岗位代录。
- 所有写入都要先向用户展示字段、事件、证据和交接对象，得到明确确认后才调用写工具。
- 决策（GO / OPTIMIZE / HOLD / REJECT 等）仍由人确认；数据不足时必须说明“数据不足”，不能猜测 EAC、利润或金额。

## 标准执行顺序

1. **确定项目和身份**：先询问或读取 `project_id`，确认当前登录岗位；不替用户猜项目，不使用未登记身份。
2. **读取岗位契约**：调用 `buildcostiq_get_role_workbench_contract`。只保留当前岗位的 `input_fields`、`output`、`hands_to` 和 `maps_to`，不要把所有岗位的表单混给用户。
3. **读取当前工作面**：调用 `buildcostiq_get_workspace_snapshot` 或 `buildcostiq_get_role_work_products`。检查当前项目 revision、待接收成果、已有 Event/Evidence/Source 引用和未完成项。
4. **收集本岗位事实**：只收集契约中的必填字段。每条成果都尽量关联 `event_id`、`evidence_refs` 和 `source_refs`；缺原件时记录缺口，不用估算值替代。
5. **形成交接包**：根据契约的 `hands_to` 选择交接对象，写清 collaboration note。交接对象必须属于契约，不可越权发送给无关岗位。
6. **人工确认**：用简短摘要展示项目、岗位、字段、证据、交接对象和将要写入的状态，询问用户是否保存。没有确认不得调用 `buildcostiq_submit_role_work_product`。
7. **保存并回读**：确认后调用 `buildcostiq_submit_role_work_product`，传入 `confirm=true`。返回 `product_id`、状态、交接对象和映射的 Core/P01–P09；随后再次读取成果，确认已经落盘。
8. **交付可视化复核**：需要完整页面复核时打开 `http://127.0.0.1:8787/` WebUI。MCP 是工作流入口，WebUI 仍是项目可视化和人工审查入口。

## 岗位最小工作面

| 岗位 | 主要成果 | 常见交接 |
| --- | --- | --- |
| 项目经理 | 指标、风险、经营决策确认 | 造价经理、技术负责人、生产经理 |
| 造价经理 / 造价员 | 合同、清单、零号台账、成本计划、变更与审核资料 | 项目经理、技术负责人、生产经理 |
| 技术负责人 | 图纸/方案/技术确认及变更依据 | 造价、生产、施工员/测量员 |
| 生产经理 | 计划、进度、实物量和分包协同确认 | 项目经理、造价、施工员/测量员 |
| 施工员/测量员 | 现场记录、放样、实测成果（可按工程拆分或合并） | 生产、技术、质量、造价 |
| 质量负责人 / 试验检测员 | 检查、验收、试验报告和质量证据 | 技术、生产、资料、造价 |
| 资料员 | 版本、归档、成果包和证据索引 | 全岗位按契约交接 |
| 安全员 | 隐患、整改和安全证据 | 生产、项目经理、资料 |
| 采购员 / 仓管员 | 采购、到货、收发料和材料台账 | 生产、造价、资料 |
| 行政人员 | 经项目经理授权的人员与行政协同 | 项目经理；不代替专业岗位录入 |

上表只是学习提示，真实字段、交接和权限以 MCP 返回的岗位契约为准。

## 输出格式

完成一次工作后，简明报告：

1. 项目与岗位；
2. 已保存的 `product_id` 和状态；
3. Event / Evidence / Source 引用；
4. 交接对象和下一步；
5. 缺失资料、需要人工确认的决策或权限限制。

不要报告没有在工作区或证据中出现的金额、人员、进度或利润。其他支持 MCP 的平台可以复用同一组工具和本 Skill；远程化、OAuth 和 HTTP 适配属于后续适配层，不改变本地 Core。
